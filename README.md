# 경민물류 배차 앱

종이·엑셀 "경민물류 일정표"를 휴대폰 중심 앱(PWA)으로 옮긴 배차 프로그램입니다. 휴대폰과 PC가 같은 데이터를 보고, 엑셀로 내보내고 올릴 수 있습니다.

- 프론트: React + TypeScript + Vite, PWA (홈 화면 설치, 오프라인 보기·입력)
- 클라우드: Supabase (PostgreSQL, 로그인, 실시간 동기화, RLS 권한, 사진 저장소, 매일 새벽 스케줄러)
- 엑셀: ExcelJS · 날짜: dayjs (Asia/Seoul 고정)

## 1. 바로 실행 (데모 모드)

```bash
npm install
npm run dev        # http://localhost:5173
```

`.env`가 없으면 **데모 모드**로 열립니다. 서버 없이 **그 기기 브라우저에만** 저장됩니다.

처음 열 때 시작할 데이터를 고릅니다.
- **기본 명단만** (실제 입력용): 선박·차량·직원·근무지·거래처 기본 명단과 현장 고정 근무만 들어 있고, 오더는 비어 있습니다.
- **예시 포함** (연습용): 요구사항의 예시(전날 육지 상차 9915 → 오늘 제주 하차, 9914 선박 이어짐, 8948 야간 감귤 등)가 오늘 날짜 기준으로 들어갑니다.

### 데모로 실제 데이터를 입력할 때

1. **한 기기에서만 입력하세요.** 데모는 기기끼리 공유되지 않습니다. PC 한 대나 배차 담당 휴대폰 한 대를 정해서 쓰세요.
2. **설정 → 데이터 보관 → 💾 백업 파일 저장**을 자주 누르세요. 3일 넘게 백업하지 않으면 화면 위에 노란 알림이 뜹니다.
   - 브라우저 데이터를 지우거나 시크릿 창을 쓰면 데모 데이터가 사라집니다. 백업 파일이 유일한 보험입니다.
   - 다른 기기로 옮길 때는 그 기기에서 **📂 백업 불러오기**를 하면 됩니다.
3. 명단이 많으면 **설정 → 엑셀 업로드**로 한 번에 넣을 수 있습니다.
4. 서버(Supabase)를 연결할 때(아래 2절)는 관리자로 로그인한 뒤 **설정 → 데이터 보관 → ⬆ 데모 데이터 서버로 옮기기**에서 백업 파일을 고르면 전부 옮겨집니다. 같은 항목은 덮어쓰기라서 여러 번 실행해도 중복되지 않습니다.
   - 데모에서 올린 사진은 백업 파일 안에 들어 있어서 그대로 보입니다. 다만 서버 저장소(Storage)로 옮겨지지는 않습니다.

```bash
npm test           # 도메인 규칙 단위 테스트 (반복 발주 · 상차→하차 연결 · 선박 이어짐 · 정비 · 엑셀)
npm run build      # 배포용 빌드 (dist/)
```

## 2. Supabase 연결

1. supabase.com에서 프로젝트를 만듭니다.
2. SQL Editor → New query에 **`supabase/setup_all.sql`** 내용을 통째로 붙여넣고 Run 합니다 (모든 테이블·권한·실시간·사진 버킷을 한 번에 만듭니다).
   - 그다음 새 query에 `supabase/seed.sql`(선박·차량·기사·거래처·현장근무 기본 명단)을 붙여넣고 Run 합니다. 데모에서 입력한 데이터를 옮길 거면 seed는 건너뛰고 아래 4번 뒤에 백업 파일을 올립니다.
   - `setup_all.sql`은 `supabase/migrations`를 묶은 파일입니다(`npm run setup:sql`로 다시 만듦). 이미 설정한 서버에는 새로 추가된 migration 파일만 실행하세요.
   - Supabase CLI를 쓴다면 `supabase db push` 후 `psql -f supabase/seed.sql`
   - Authentication → Sign In / Providers → Email에서 **Confirm email**을 끄면 가입 즉시 로그인됩니다(켜 두면 받은 메일의 링크를 눌러야 로그인됩니다).
3. `.env.example`을 `.env`로 복사한 뒤 Project Settings → API의 URL과 anon key를 넣습니다.
4. 앱에서 **처음 가입한 사람이 관리자**가 됩니다. 이후 가입자는 "조회(기사)"이며, 관리자가 설정 → 사용자 권한에서 배차·관리자로 바꾸거나 기사와 연결합니다.

### 매일 새벽 스케줄러 (반복 발주 8주 연장)

```bash
supabase functions deploy daily-maintenance
```

Vault에 `project_url`과 `service_role_key`를 넣은 뒤 `supabase/migrations/20261020000003_scheduler.sql`을 실행합니다. 매일 03:00(KST)에 반복 발주와 고정 근무를 오늘+8주까지 연장하고 정비 알림·월말 금액 미입력 알림을 만듭니다. 13:00에는 배차 대기 상차 알림을 만듭니다. 앱도 관리자·배차가 열 때 같은 연장을 한 번 더 하므로, 스케줄러가 멈춰도 일정은 비지 않습니다. (같은 날짜가 중복으로 생기지 않도록 DB 고유 인덱스가 막습니다.)

Edge Function은 앱과 **같은 도메인 코드**를 씁니다. `src/domain`을 고친 뒤에는 `npm run sync:functions`를 실행하세요. 복사본이 다르면 테스트가 실패합니다.

## 3. 배포 (Vercel)

1. GitHub 저장소를 Vercel에 Import합니다 (Framework: Vite, Build: `npm run build`, Output: `dist`).
2. Environment Variables에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`를 넣습니다 (선택: `VITE_KAKAO_REST_KEY`).
3. 배포 주소를 휴대폰으로 엽니다.
   - Android Chrome: 메뉴 → "홈 화면에 추가" / "앱 설치"
   - iPhone Safari: 공유 → "홈 화면에 추가"

`vercel.json`은 새로고침해도 화면 주소가 유지되도록 설정합니다. Netlify나 Cloudflare Pages도 같은 방식(SPA 리라이트)으로 배포할 수 있습니다.


## 이메일 백업 (일주일마다 자동)

백업 파일을 지정한 이메일로 보냅니다. 데모 모드에서도 동작합니다. 이메일은 서버를 거쳐야 보낼 수 있어서, Vercel에 들어 있는 작은 발송 기능(`api/backup-email.js`)과 무료 이메일 발송 서비스 **Resend**를 씁니다.

1. https://resend.com 에서 가입합니다. **백업을 받을 이메일 주소로 가입**하세요(아래 3번 참고).
2. API Keys → **Create API Key** → 만들어진 키(`re_…`)를 복사합니다.
3. Vercel → 프로젝트 → **Settings → Environment Variables**에 넣습니다.
   - `RESEND_API_KEY` = 복사한 키
   - `BACKUP_EMAIL_TO` = 받을 이메일 (여러 개면 쉼표로)
   - 도메인이 없으면 Resend는 **가입한 이메일로만** 보낼 수 있습니다. 다른 주소로 받으려면 Resend에서 도메인을 인증하고 `BACKUP_EMAIL_FROM`(예: `경민물류 <backup@내도메인>`)을 넣으세요.
4. Deployments → 맨 위 배포 ⋯ → **Redeploy**를 누릅니다.
5. 앱 → 설정 → 데이터 보관 → **📧 지금 이메일로 보내기**로 시험합니다.

동작 방식:
- 관리자·배차 계정으로 앱을 열 때, 마지막 이메일 백업이 7일이 지났으면 자동으로 보냅니다. 앱을 열지 않은 주에는 보내지 않습니다.
- 첨부는 압축 파일(`gyeongmin-backup-날짜.json.gz`)입니다. 복원할 때는 **설정 → 백업 불러오기**에서 그 파일을 그대로 고르면 됩니다.
- 받는 주소는 서버(Vercel 환경변수)에만 있어서 앱 화면에서는 바꿀 수 없습니다.
- 사진이 아주 많아 4MB를 넘으면 이메일로 못 보냅니다. 그때는 💾 백업 파일 저장을 쓰세요.

## 업무 기능 메모

- **기사 근무조**: 월수금 · 화목일 · 월수 · 토요일 · 주말 · **알바** · 부산상주 · 서울상주
  - 알바는 정해진 근무일이 없습니다. 근무형태를 넣은 날만 출근으로 잡혀 배차 목록 "오늘 근무"에 나옵니다. 일정표에서 알바를 기사로 고르면 근무형태 입력이 바로 뜹니다.
- **근무형태**(여러 개 가능): 주간근무, 야간근무, 특근, 출장, 장거리, 단거리, 야간단거리, 시간외근무
  - 일정표 차량 칸 → 근무형태, 또는 차량·기사 → **근무현황**에서 날짜 칸을 눌러 넣습니다.
- **월간 근무현황**: 차량·기사 → 근무현황. 기사×날짜 표와 형태별 합계를 보여 주고, 엑셀로 내려받을 수 있습니다. "배"는 배차됐지만 형태를 안 넣은 날입니다.
- **선박**: 차량·기사 → 선박에서 선박을 눌러 수정합니다.
  - 제주 출발(상행) 시간과 **기항지별 하행 시간**을 따로 넣습니다.
  - 육지 하행선박을 고를 때 "퀸메리 · 목포 01:00"처럼 기항지별로 나오고, 칸에는 `퀸메리 (목포)`로 저장되어 다음 날 반대편으로 그대로 이어집니다.
- **오더**:
  - 상차지 → 하차지를 입력합니다. 품목·거래처에 주소가 있으면 자동으로 채웁니다.
  - 수량은 `10파렛트`, `3대`, `12p`, `5박스`처럼 숫자 뒤에 단위를 써도 됩니다.
- **당일 왕복**: 상차에 "당일 왕복"을 켜면 다음과 같이 처리됩니다.
  - 반대 지역 하차가 **같은 날짜**로 들어갑니다.
  - 차량은 출발한 쪽에 그대로 있는 것으로 셉니다. 다음 날 위치가 바뀌지 않습니다.
  - 상차한 지역에는 점선 **왕복** 줄로 표시됩니다.
- **줄 순서**: 일정표 위 **↕ 줄 순서**를 누르고, 차량을 누른 뒤 들어갈 자리의 차량을 누릅니다. ▲▼로 한 칸씩 움직일 수 있고, PC는 끌어다 놓기도 됩니다. 모든 날짜에 같은 순서가 적용됩니다.
- **자동 저장**: 바꾸는 즉시 이 기기에 저장되고, 일정표 위에 "✓ 자동 저장됨 시:분"이 표시됩니다. 서버를 연결하면 서버에도 바로 올라갑니다.
- 차량 목록은 차량번호, 기사 목록은 이름 **가나다순**입니다.
- **기사 지정**: 차량에 기본 기사를 두지 않습니다. 기사는 매일 바뀌므로 일정표 차량 칸에서 그날 지정합니다.
  - 기사 화면의 주행거리 입력은 그날(없으면 최근에) 배차된 차량으로 나옵니다.
- **운송 방법**(오더 입력·수정): **직영 / 용차 / 화주배차**
  - 용차·화주배차는 차량번호 대신 업체·기사·차량번호·연락처를 글자로 적습니다.
  - 배차 대기로 세지 않고 일정표 아래 **용차·화주배차** 묶음(주황 점선)에 모입니다.
  - 노란 배차 칸을 눌러 차량 목록 맨 위의 **🚚 용차로 / 🏭 화주 배차로**를 눌러도 됩니다.
- **벌크(화물만 선적)**: 상차에서 "벌크"를 고르면 다음과 같이 처리됩니다.
  - 차량은 배를 타지 않고 그 자리에 남습니다.
  - 반대편 하차는 **차량 없이** 배차 대기로 들어가서, 도착지에서 다시 배차합니다.
- **하차 날짜 조정**: 상차의 "반대편 하차 날짜"를 기본(선박 설정) / 같은 날 / +1일 / +2일 중에서 고릅니다. 선박·벌크 마감으로 다음 배를 타면 늦게 고르면 됩니다.
- **다른 물류업체가 예약한 배**: 선박을 고를 때 "예약해 준 업체"에 이름을 적으면 칸에 `대한물류 예약`으로 표시되고, 다음 날 반대편으로도 그대로 이어집니다.
- **하단 탭**: 배차 · **일정표** · 오더 · 거래처 · 차량·설정
  - **배차**: 육지/제주/현장근무/미배차를 탭으로 나눠 입력하는 화면 (예전 "일정표")
  - **일정표**: 한 화면에 **육지(위) · 제주(아래)**를 한눈에. 칸을 누르면 배차 화면과 똑같이 보기·수정됩니다. 기사 화면의 "전체 일정 보기"도 이 화면입니다. (월별 화면은 없앴습니다)
- **기사 팀**: 기사 등록에 "팀"을 넣습니다. 이미 있는 팀은 눌러서 고르면 됩니다.
  - 기사 선택 목록이 **팀별로 묶여** 나오고, 위의 팀 버튼(숫자 = 오늘 근무 인원)을 누르면 그 팀만 보입니다.
  - 팀을 비우면 근무조로 묶입니다. 기사 목록과 월간 근무현황도 팀 순서로 정렬됩니다.
- **차량 순서**: 일정표 바로 위 **↕ 차량 순서 바꾸기**를 누릅니다. 기사가 지정된 차량은 차량 칸을 눌렀을 때 나오는 **▲ 위로 / ▼ 아래로**로도 됩니다.
- **배차 안 된 짐은 상차 지역에만**: 차량 없이 등록한 상차는 상차 지역의 배차 대기에만 나옵니다. 상차에 차량을 배정하면 반대편 하차가 그 차량 줄에 나타납니다. 벌크 하차와 직접 입력한 미배차 하차는 그 지역에 계속 나옵니다.
- **품목 변경**: 등록한 오더를 수정할 때 "품목 변경 ›"을 누르면 같은 거래처의 품목을 다시 고를 수 있습니다. 연결 하차도 같이 바뀝니다.

### 설계 메모

- **금액 분리**: `daily_orders`에 금액 컬럼을 두지 않고 `order_revenue`·`product_pricing` 테이블로 분리했습니다. 한 테이블 안에서 컬럼 단위로 사용자별 권한을 다르게 주는 것은 Supabase RLS로 안 되기 때문입니다. 기사·조회 계정은 이 두 테이블의 행을 아예 받지 못합니다.
- **차량 하루 한 줄(`vehicle_days`)**: 선박·상태·기사는 차량 단위 정보입니다. 그래서 짐이 없어도 "선박만" 넣으면 다음 날 반대 지역 줄이 생깁니다.
- **오프라인**: 변경은 화면에 바로 반영되고 IndexedDB에 저장됩니다. 연결되면 전송하고, 다른 사람 변경은 Realtime으로 받습니다. 충돌하면 마지막 저장이 이기고, 편집 중인 항목이 바뀌면 알림을 띄웁니다.
- **변경 이력**: 모든 테이블에 트리거로 `audit_log`(누가·언제·전/후)가 남고, 품목·거래처 화면 하단에 표시됩니다.
- 제주 오전 = 하차(`unload`), 제주 오후 = 상차(`load`)로 저장합니다.

## 아직 남은 것 / 한계

- **첨부 일정표 원본은 받지 못했습니다.** 시드에는 요구사항 본문에 나온 선박·차량번호·직원·근무지만 들어 있고, 트럭 기사 이름은 `기사(9915)` 같은 자리표시자입니다. 엑셀 업로드 양식(설정 → 업로드 양식)으로 실제 명단을 올리면 됩니다.
- **푸시 알림**은 앱이 열려 있거나 백그라운드일 때 Realtime + 브라우저 알림으로 동작합니다. 앱이 완전히 닫힌 상태의 Web Push는 VAPID 키와 발송 서버 설정이 더 필요합니다.
- **주소 → 좌표 변환**과 "현재 위치 → 도로명 주소"는 `VITE_KAKAO_REST_KEY`가 있을 때만 됩니다. 없으면 주소 검색(다음 우편번호)과 좌표만 저장하고, 길찾기는 주소 검색으로 엽니다.
- **휴대폰에서 끌어다 놓기**는 노란 차량 칸 탭(또는 길게 누르기) → 차량 선택으로 대신합니다. 마우스로 끌어다 놓기는 PC 표에서 됩니다.
